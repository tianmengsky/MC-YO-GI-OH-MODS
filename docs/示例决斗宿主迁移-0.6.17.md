# 示例决斗宿主迁移 0.6.17-alpha

日期：2026-10-16。目标：复用用户提供的示例模组决斗实现，同时保留本项目 Minecraft GUI、旧物品注册和存档兼容。

## 最终实现

生产路径为 `DuelBridge → ReferenceHost → adapter.exe → 示例 duel_host.dll → 配套 ocgcore.dll / cards.cdb / script.zip`。每场决斗使用独立宿主进程，回调和句柄互不共用。宿主负责内核推进、消息分帧、请求生成、应答分发和 Windbot；Java 将请求转换为现有 GUI 的 ChoiceModel 和网络数据。

直接复用示例模组配套的宿主、内核、数据库、脚本、.NET 8 运行资源和 Windbot。没有把示例 Minecraft 界面、物品注册或服务器入口整体混入本项目。`NativeDuelScreen`、`NativeBoard`、现有网络协议及旧模组生命周期保留。旧 `MdproRuntime` 和探测程序保留作历史验证，生产决斗不再实例化它。

不是对示例二进制零修改：`addon/duel-host-adapter/PatchHost.cs` 在固定原宿主 SHA-256 的基础上，对 6 个方法施加受控补丁，完成四类适配：大师规则 3；只读场面快照；保留服务端已洗牌或训练起手顺序；非法人工应答后的原问题重发。卡片 Lua 和配套原生内核沿用示例。声明、计数器、素材合计等复杂编辑器仍使用宿主已分帧的原始请求字段适配现有 GUI。

## 关键修复

- 连锁是否必发取示例宿主的 `forced` 字段，取消可选连锁向内核发送整数 `-1`，不再将 special / timing 当作强制标志。真实必发效果仍不可取消。
- 额外卡组页面保持独立卡片位置和候选索引，重复卡片也能分别选择；打开额外卡组不会自动提交第一张。
- 整数应答和字节列表应答分别调用对应宿主接口；过期修订号和重复客户端包由服务端拒绝。
- 原生非法应答恢复到原问题，避免在 MSG_RETRY 上循环或无提示卡住。
- 决斗处理异步执行，Minecraft 服务端逐 tick 消费事件；投降、错误取消和关闭服务器沿用本项目生命周期与资源释放入口。
