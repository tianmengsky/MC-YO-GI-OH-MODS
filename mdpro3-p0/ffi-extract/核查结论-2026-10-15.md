## 已确认的托管声明

- YGOSharp.OCGWrapper.Api 和 Percy.Dll 均将 new_card 声明为 7 参数：
  void new_card(intptr pduel, uint32 code, uint8 owner, uint8 playerid, uint8 location, uint8 sequence, uint8 position)
- Percy.Dll.create_duel_v2 接收 uint32[] seeds；数组长度需继续核查调用点，不能按 uint64 值或 uint64 数组推定。
- Percy.Dll.start_duel 接收 intptr pduel, uint32 options；大师规则选项的编码仍需核查调用点或匹配内核源码。
- 两套 CardReader 均返回 uint32，参数为 uint32 code 和对应 CardData 指针。
- ScriptReader 返回 intptr，参数为 string scriptName 和 int32* len。
- MessageHandler 返回 uint32，参数为 intptr pDuel 和 uint32 messageType。
- 导入标记 0x204：ANSI 字符集、cdecl；委托 UnmanagedFunctionPointer 属性中调用约定值为 2（cdecl）。

## CardData 存在两个版本

YGOSharp.OCGWrapper.Card+CardData：
Code / Alias 为 int32；Setcode 为 int64；后续 Type、Level、Attribute、Race、Attack、Defense、LScale、RScale、LinkMarker 均为 int32。

Percy.CardData：
Code / Alias 为 int32；Setcode 为 fixed int16[16]（内嵌 32 字节，非指针）；后续 Type、Level、Attribute、Race、Attack、Defense、LScale、RScale、LinkMarker 均为 int32。
按顺序布局和默认对齐推导 Percy 版本大小为 76 字节，仍应由实际调用及原生验证确认。

## 对旧诊断的修正

“不崩溃”不能证明调用签名正确。2 参数 new_card 未放入卡牌，不能据此认定本 DLL 使用 OCG_NewCardInfo。
“7 参数调用崩溃”也可能由 card_reader 回调签名、写入布局、缓冲区寿命等错误引起，根因尚未证实。
不得继续将现代 OCG_CardData 的 setcodes 指针 / uint64 race 布局直接套在本 DLL 上。
