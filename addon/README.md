## 服务器动态禁限管理

旧内置 2006 禁限表不再生效。默认自定义表为空，所有卡按同名卡合计最多 3 张；管理员可设置 0（禁止）、1（限制）、2（准限制）或 3（解除自定义限制）。所有管理命令需要 OP 等级 2，服务端控制台也可执行：

    /mdpro banlist set 53129443 0
    /mdpro banlist set yugioh:dark_hole 1
    /mdpro banlist get 53129443
    /mdpro banlist list
    /mdpro banlist list 2
    /mdpro banlist set 53129443 3
    /mdpro banlist clear

卡片可使用密码、原注册 ID 或 `yugioh:<注册ID>`，支持 Tab 补全。规则保存在当前世界 `data/yugioh_mdpro_banlist.dat`；登录和修改时向客户端同步，断开连接清除客户端缓存。联机双方应同时更新本次附属模组，网络协议现为 5。

规则应用于组卡、主卡 / 额外 / 备牌合计投入和新决斗开始前检查，同名变体共用限制；已经开始的决斗继续进行。禁限表只保存规则，绝不改写卡片属性、玩家物品、实体卡表、预组发卡表或卡组盒 NBT。禁用中的卡仍可持有、收藏和从对应产品获得；开局检查会提示玩家自行调整卡组。


## 0.6.1 内存资源优化

此前并行开发的仿 MDPro3 GUI 已包含在本版：卡旁动作菜单、连锁 / 是非弹窗、选卡网格 / 搜索 / 分页、选位置与宣言卡名。部署检查对比旧版与新版五个核心 GUI 类的实际字节，防止打包时丢失。交互夹具仍使用 `-PuiSmoke`。

88 张 ygostar 旧物品贴图原为 2048×2048，通过附属资源覆盖为 256×256（RGBA PNG，保留透明度、路径、注册名及 UV）。工作区冻结输入不变；重生成 `python addon/tools/optimize_item_assets.py`。物品图集实测从 32768×16384 降至 4096×4096，含原 4 级 mip 的 RGBA 分配约由 2.67 GiB 降至 85.25 MiB，减少 96.875%。这是该图集的占用，不能等同整个游戏进程内存降幅。

按需加载的卡面 / 立绘共用 64 MiB、最多 192 张的 LRU 缓存，帧末淘汰并实际释放 GPU 纹理；一帧内绘制期间允许临时超过预算，避免提前删除尚未提交绘制的纹理。断线、资源重载和原贴图失效接口清理缓存。MDPro 运行库 / 卡表 / 脚本的 SHA-256 校验改为 64 KiB 流式读取，不改 ABI、Lua、卡片数据或预组配方。

`-PvisualSmoke` 同时覆盖 88 张资源实际选中、GL 图集尺寸、240 张卡面 + 180 张透明立绘的缓存压力、纹理删除 / 重载及完整资源重载；证据 `generated/memory-smoke-result.json`。Java 17、最大堆 1.5 GiB 的开发客户端已通过这组显示检查；真实世界和联机仍由用户验收。

用户实际崩溃日志为原生分配失败，启动器当时选择 Java 25，最大堆约 5.1–5.3 GiB。该 16 GiB 设备建议在 PCL 此版本设置中使用 Java 17，先分配 3 GiB，重负载世界可用 4 GiB，给系统、图形驱动、原生库留出空间。没有修改启动器全局设置或系统分页文件。

现提供 Forge Jar-in-Jar 单文件发行，内部保留 `yugioh`、`yugioh_interaction_fix`、`ygostar`、`yugioh_mdpro_addon` 的注册身份。安装文件为 `yugioh-mdpro-integrated-0.6.2-alpha.jar`，替代上述四个独立 JAR；GeckoLib 继续独立保留。原命名空间、注册名及世界存档不迁移。文件合并本身不减少运行内存，原有图集和缓存优化全部保留。

## 单文件发行构建与验证

`content/integrated-release.json` 锁定四份已审核来源的 SHA-256。外层完整保留当前附属所有原条目，并在 `META-INF/jarjar/metadata.json` 声明三个原始依赖 JAR；嵌入 JAR 与原安装文件逐字节相同，保留各自清单、Mixin、refmap 和资源。仍需实例中的 `mdpro-runtime/` 原生内核 / 卡表 / Lua，不包含在合并 JAR 内。

在工作区根目录执行：

```text
python addon/tools/package_integrated.py build
python addon/tools/verify_integrated_client.py visual
python addon/tools/verify_integrated_client.py ui
python addon/tools/package_integrated.py deploy
```

Gradle `integratedRelease` 会先执行 `reobfJar` 再生成单文件安装包。更新来源时必须同步审核集成清单的版本和哈希，不允许无检查地打入新来源。部署另需已完成 `generated/integrated-native-smoke.log` 原生决斗验证；交付记录见 `generated/整合包交付-2026-10-15.md`。

整合验证直接使用目标实例的正式 Forge 47.4.28 和 Java 17 启动隔离客户端，`run-client/mods/` 中仅整合包和 GeckoLib；不使用 Gradle userdev、松散开发类或额外 `--mixin` 参数。显示夹具覆盖中文 / 卡图 / 产品 / 投影 / 图集 / 缓存及完整资源重载；GUI 夹具覆盖实际点击操作。`package_integrated.py verify` 逐项核验所有外层原条目和嵌入来源；`deploy` 仅在同一 SHA 的客户端验证通过后备份原四包并替换，失败自动恢复已删除的原包。旧 `deploy_historical_content.py` 遇到已安装整合包会中止，防止重复安装。

## 0.6.2 公开世界投影

同维度、距决斗固定锚点 32 格内的所有玩家均可看见世界中的卡面与怪兽投影，无需加入决斗。双方也统一使用此公开世界渲染；决斗 GUI 继续使用各自的私有数据。

公开网络包只包含双方场上五格怪兽、五格魔陷、锚点、维度及攻击动画事件。盖卡身份 / 数值 / 稀有度匿名化，不发送手牌、牌组、额外卡组、操作选项或私有对局快照。不会为旁观者打开决斗 GUI，也不赋予操作权限。按原引擎保留怪兽模型 / 立绘 / 卡图回退和 32 格显示距离。

场面变化即时同步，等待操作期间每秒刷新，靠近途中补发；离开范围、维度变化、决斗结束、断开连接时清理，客户端另有 5 秒过期保护。每场决斗单独保存场面和动画，允许同时观看多场；每次广播只查询一次原生场面，供附近全部玩家共用。网络协议升级为 **6**，服务器与全部客户端需一起使用 0.6.2。

新增 GameTests 覆盖第三方资格、原 32 格边界、跨维度隔离、实际原生召唤 / 盖放后的公开数据；显示夹具新增两场公开棋盘的共享世界绘制、动画隔离、结束 / 换维度清理及不修改私有 GUI 的检查。真实三人联机仍由用户验收。
