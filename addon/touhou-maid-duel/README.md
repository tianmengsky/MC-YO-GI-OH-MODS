# Touhou Little Maid × Yu-Gi-Oh! Duel Addon

适用于 Minecraft 1.20.1 / Forge 47.4.28 的 Yu-Gi-Oh 与车万女仆附属模组。

## 使用

1. 玩家主手装备 Yu-Gi-Oh 决斗盘。
2. 被驯服女仆副手装备决斗盘。
3. 女仆可用背包中放入已准备好的卡组盒。
4. 右键女仆打开原模组的“对局赛制”页面，设置规则并选择单局、三局或五局后开战；取消页面不会冻结女仆。卡组盒按背包槽位从前到后选择第一个合法卡组盒，确认时重新读取。
5. 决斗期间女仆优先站在棋盘对面安全位置，附近空间不足时使用原位置附近的安全地面；没有安全位置则拒绝开局。女仆停止工作、固定朝向，防止窒息；换副卡组阶段继续固定，整场结束或玩家离线后恢复原状态。原位置已被堵住时寻找附近安全位置。
6. 决斗界面的女仆立绘会使用女仆当前模型，并将 YGO 人机对手（对手 AI 席位）的抽卡、攻击、受伤、召唤、发动、盖放、防御等动作映射到人形骨骼。酒狐及其衍生 Gecko 模型使用完整骨骼适配；经典人形模型缺少细分骨骼时自动使用简化动作或安全回退。
7. 0.1.5 起动作按世界朝向重定向：先算原生人机骨骼的世界四元数，身体/头/腿用 `(x,y,-z)`（X 前后、Y 转身同向，Z 侧摆镜像）换算到 Gecko 空间，再用女仆父骨骼的当前世界朝向反解局部旋转；**双臂直接复制原生局部旋转**（同侧手臂，避免镜像把左臂/副手盘甩到身后）。身体因此朝向**屏幕左侧/棋盘**，与原生对手一致；此前全骨 `(x,-y,-z)` 会让 Root 转向屏幕右侧。女仆腿挂在 `AllBody`、原生腿挂在 `all` 下的层级差一并修正。未映射的头发、尾巴、耳朵、裙摆和定位骨骼继续播放女仆自己的动画。
8. 姿势来源使用原生对手立绘当帧传入的 `clip/seconds`（`PuppetPose.capture`），不再通过可能优先玩家轨道的 `DuelPuppetActions.poseFor`，因此绑定的是对手人机动作。首轮 0.1.5 的 `nativeWorld` 存在四元数原地乘法别名，会让世界目标被父骨骼污染并把立绘移出画面；已改为 `new Quaternionf(parentWorld).mul(local)`。决斗盘保持在**副手（左手）**（原生人机同样是副手盘）；双臂局部旋转 + 身体/头/腿 `(x,y,-z)`，让左手的盘在待机和 `中二拍卡` 里端到胸前，身体朝屏幕左侧。以上均用工作区 `run-debug/` 调试场景的 `debug-view-0/5.png` 确认。

## 构建

```powershell
gradle compileJava jar reobfJar --no-daemon
```

产物：`build/libs/touhou-little-maid-yugioh-duel-addon-0.1.5.jar`（最终 SHA-256：`7F7A3B9310A4B9E34B744322B4BA492D217D5E0267D13D67A4E5FA71E20282F2`）

0.1.4 曾恢复身体、头部和腿部对 YGO 人机立绘的直接局部旋转数值，仅对酒狐人形手臂链反转局部 Z 弯曲方向；该做法在 0.1.5 已被四元数世界朝向重定向整体替换。

不要直接复制到原游戏目录；先在工作区隔离实例验证，再由用户决定部署位置。

`-PmaidSmoke` 额外编译 `src/smoke/java`，用于正式 Forge 启动时强制加载并验证服务端 Mixin；发布前执行不带该参数的 `clean compileJava jar reobfJar`，测试类不进入发行包。
